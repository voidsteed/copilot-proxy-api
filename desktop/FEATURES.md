# Desktop feature map

The desktop app is version 0.0.8 build 8. Its release history started at 0.0.1. The existing CLI keeps its release history.

| Feature | Expected behavior | Verification |
| --- | --- | --- |
| GitHub sign-in | Share native authorization with the CLI. Show a device code, obey polling limits, and preserve the current account when replacement fails or is cancelled. | Local upstream fixtures, private CLI commands, and the rendered sign-in flow. Live sign-in is recorded separately. |
| Account storage | Keep GitHub credentials native and persist encrypted credentials. CLI startup reuses the installed app's saved account. Native sign-out cannot revive an older plaintext CLI token. Explicit CLI tokens remain session-only. | Native storage and provenance tests. Actual encrypted recovery requires a native user session. |
| Shared gateway | Attach to the configured running CLI before starting another service. With the desktop installed, CLI startup connects to or wakes the native owner. Both interfaces see its connection, account, options, catalog, quota, and activity. | Existing-CLI regression, two-client private transport tests, startup and lifecycle checks, and native UI. |
| Refresh after CLI startup | If the app opens before the configured CLI, Refresh discovers and attaches to that listener. Preserve native ownership, saved credentials, runtime policy, and agent files. | Failing-before late-listener regression, ownership and refresh tests, and a packaged native Refresh workflow. Real Codex execution against the existing CLI is recorded separately. |
| CLI status when quota is unavailable | Identify the CLI from its local greeting, authenticated catalog, and request-log schema. Check local health independently from GitHub quota. Keep the last validated quota and activity when optional reads fail. | HTTP regressions and a packaged native workflow with quota held open, followed by real listener shutdown. |
| Local gateway | Bind IPv4 and IPv6 loopback. Preserve the active inference authentication policy. Explicit Stop can cancel owned requests. Account and option replacement drain requests before switching. | Actual HTTP, sustained streams, stale leases, a controlled child process, and the native UI. |
| Protocols | Preserve OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, and their supported streaming behavior. | Existing proxy tests plus real HTTP through the desktop-owned Node runtime. |
| Models | Show the active proxy's catalog, capabilities, and limits. Each agent keeps its own exact configured model, including aliases. Missing-model proposals are separate per agent. Catalog browsing changes no agent. | Independent-model and alias tests, the rendered agent tabs, and live catalog discovery. |
| Usage | Check quotas from the active owner. Keep slow optional reads separate from local health, let explicit refresh check immediately, and show the successful check date and calendar reset date. Distinguish unlimited, unavailable, and zero remaining. | Delayed HTTP, pacing and coalescing, failure and recovery, timezone tests, and packaged native refresh. |
| Agent setup | Inspect Claude Code, Codex, and OpenCode. Configure adds only missing fields and preserves existing values, comments, permissions, and symlinks. Open the selected config folder. Matching configured agents launch with their normal command. | JSONC and TOML preservation tests, concurrent-edit refusal, repeat actions, native buttons, and copied commands. |
| Test request | Send the selected model a real request through the local gateway and show its response or an actionable error. | Controlled upstream response, completed activity, and live Copilot execution recorded separately. |
| Activity | Import older CLI inference records and retain them across polling. Older traces report observations, with unknown model and token fields. Managed requests report completion, failure, or cancellation after outgoing finish or close. | Real HTTP and socket tests, streaming cancellation, native activity, clearing, and redaction checks. |
| Reused CLI request IDs | Use request ID and start time together to identify a row. Keep chronological order, row counts, and one-row expansion stable through polling when a client reuses its ID. | Native renderer regression with repeated IDs, new records, detail expansion, and the five-row Overview limit. |
| Legacy startup and native Keychain | Discover a configured CLI before loading the dormant native vault. Check OS encryption only during an operation that uses encrypted data, with native restoration and saved-key discovery preserved. | Encrypted-file controller regression, signed normal-mode zero-crypto startup proof, and actual profile launch. |
| Settings | Apply explicit runtime changes through one owner. CLI defaults do not reset a running service. Keep appearance, shell, probe model, and per-agent proposals as UI preferences. | Explicit-option tests, UI save, invalid input, CLI changes, and restart. |
| Preferences during CLI observation | Save display, shell, and model preferences while preserving the dormant native port, runtime options, and encrypted authentication. Keep the active CLI connection visible. | Private controller fixtures, successive writers and reload, failures, and native preference readback. |
| Desktop lifecycle | Offer native tray actions, a single app instance, safe close behavior, and complete quit cleanup. | Actual Electron launches. Platform-specific behavior requires the matching OS. |
| Packaging | Bundle the runtime for macOS, Windows, and Linux. Users need neither Node nor Bun. Include PDF dependencies and worker assets. | Local macOS launch and package checks. Native Windows/Linux CI must be distinguished from checks run on this Mac. |

The app supports one active Copilot account. Other providers, multiple simultaneous accounts, cloud sync, signing, and publishing are outside this development scope.

Older CLI processes expose observation endpoints but have no account, runtime control, or drain protocol. The desktop keeps those processes running and marks their controls as managed in Terminal. Full shared control requires a controlled restart into the updated implementation. Source edits alone cannot update an already running process.
